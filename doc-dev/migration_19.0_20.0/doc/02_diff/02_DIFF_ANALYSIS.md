## Ringkasan untuk Review — Keputusan Default (Tidak Blocking, Didokumentasikan untuk Transparansi)

1. **DIFF-01 (`list_optional_show`):** default = **PORT AS-IS**, tidak extend override modul untuk mendukung fitur baru ini. Alasan: menambah dukungan = menambah fitur baru ke kode modul (dilarang `CLAUDE.md` kecuali user eksplisit minta), dan tidak ada dampak fungsional negatif (bukan crash, cuma fitur baru yang tetap inert — sama seperti sebelum modul ini pernah "sadar" fitur ini ada). **User bisa minta diaktifkan eksplisit kapan saja setelah migrasi ini selesai, sebagai perubahan terpisah yang disengaja.**
2. **DIFF-02 (`logOutItem` export dihapus):** **WAJIB diperbaiki** di step 3/6 — hapus `import { logOutItem as OriginalLogOutItem } from "@web/webclient/user_menu/user_menu_items";` dan `export { OriginalLogOutItem };` dari `user_menu_items.js` modul. Ini kompatibilitas wajib (bukan pilihan), BUKAN perubahan business logic — `OriginalLogOutItem` sudah dikonfirmasi dead code sejak 17.0 (BSL-007).
3. **DIFF-03 (ACL `res.partner` self-write):** tidak ada aksi kode diperlukan — TAPI dicatat sebagai `MF-01` di `FINDINGS.md` (lihat di bawah) supaya step 5 (Acceptance Criteria) dan step 9/10 (testing) tidak menulis ulang assertion "write harus gagal silent untuk `base.group_user` biasa" tanpa verifikasi ulang terhadap 20.0.
4. Item 1 dan 3 di atas TIDAK memenuhi kriteria `ESCALATION` formal `CLAUDE.md` (tidak ada keputusan berisiko tinggi tanpa default jelas) — keduanya punya default yang jelas (port as-is / catat untuk step selanjutnya) dan risikonya rendah-sedang, bukan tinggi. Item 2 juga tidak butuh eskalasi karena fix-nya wajib dan tidak ambigu (satu-satunya cara aman menghapus dead import yang sudah pasti unused).

**Lanjut ke Step 3 (Migration Spec) tanpa menunggu keputusan tambahan dari user**, sesuai instruksi "JALAN TERUS" `CLAUDE.md` — tidak ada blocker faktual di step ini.
